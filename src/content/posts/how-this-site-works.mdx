This site is a desktop. Windows open, drag and close. Behind them, an agent sits in the wallpaper: a core, six tool nodes on tethers, and a quarter of a million points of data moving between them. Everything is drawn in two colors, a pale LCD green (`#C9CEBB`) and a dark olive (`#262E1B`). There is no third color anywhere on the page.

I wanted the site to look like what I work on. Most of my job is AI agents and the data systems underneath them, so the picture is an agent with data flowing through its tools. These are notes on how it's built.

## One GPU, one dither

The wallpaper is two very different things drawn by one renderer.

The agent is raymarched. A fragment shader describes the core, the tool nodes and the ring around them as signed distance functions, then marches a ray through every pixel to find the surface, light it and shade it with soft shadows.

The data is 262,144 particles. Their positions and velocities live on the GPU and update with WebGL2 transform feedback, so the CPU never touches them. Each frame, every particle adds a little ink to one cell of a half-float buffer at the site's pixel scale.

Both meet in a single composite pass. It raymarches the hub, multiplies the particle ink into it, and turns the result into exactly two colors with an 8×8 Bayer dither:

```glsl
float bayer2(vec2 a) { a = floor(a); return fract(a.x * 0.5 + a.y * a.y * 0.75); }
float bayer4(vec2 a) { return bayer2(0.5 * a) * 0.25 + bayer2(a); }
float bayer8(vec2 a) { return bayer4(0.5 * a) * 0.25 + bayer2(a); }
```

That's the closed form of the classic matrix, with no lookup texture. A unit test proves it matches the recursive 8×8 matrix. Because the particles and the agent go through the same dither, the particles read as 1-bit pixel dust instead of glowing sprites pasted on top.

The dither pattern is locked to the page, not the screen. The threshold indices are offset by the scroll position, so when you scroll, the pattern moves with the document instead of shimmering in place.

## What the points mean

The count isn't arbitrary. My Insights API serves about 1.2 billion records a month, so each of the 262,144 points stands for about 4,578 of them. The caption computes that from the live count, so on a phone, where the scene runs 32,768 points, it reads about 36,621.

## Three moments

**The boot.** On your first visit, points stream in on curl-noise currents and spell my name, sampled from the same pixel font the menus use. Then they fall into the agent's core and the desktop appears. It plays once a session. A short inline script decides before first paint whether the boot will play: desktop width, motion allowed, not seen yet. Only then does it hide the hero, so the page never flashes. If anything goes wrong, the hero comes back after eight seconds regardless.

**The wallpaper.** Points travel along the tethers between the core and the tools, and a tether surges after its tool dives into the core, which is a tool call. Your cursor pushes the points away, and they spring back.

**The career trace.** The Experience window shows my career as a distributed-trace waterfall. When it's on screen, the points pour out of the agent into the three role bars. Those bars sit inside a draggable window, which other windows can cover, so drawing particles in the wallpaper and lining them up with the window wouldn't layer correctly. Instead, each bar holds a small 2D canvas that copies its patch of the GPU canvas every frame. The bar is ordinary DOM, so it stacks, drags and scrolls like everything else in the window.

## The rest is a normal web app

Under the wallpaper it's a Next.js app, and most of it is deliberately plain.

Every window body is rendered on the server. Closed windows are still in the HTML, so search engines and screen readers get every word. Only the interactive parts run on the client: the window chrome, the trace, a copy button and the scene. Case files and posts own URLs: opening one pushes `/work/<slug>` or `/blog/<slug>`, and the back button closes it. Load that URL directly and the desktop opens with the file already showing.

The only time-dependent input on the site is "now", for the end of the trace. Next.js 16 makes you say how to handle the clock, so the trace geometry is computed on the server, cached for a day, and handed to the client. The page stays static, and the bars keep up with the calendar without a redeploy.

On a phone it becomes a calmer layout I call Pocket mode: one column, name first, a dock in the thumb zone, and the scene in a small square. It runs 32,768 points at 30 frames a second, never fights your scrolling, and goes to sleep after 20 seconds without a tap.

## Guardrails as tests

Some rules matter more than any one feature, so they're tests rather than good intentions:

- No internal project names or colleagues' names appear in the content. The test checks hashes, so the banned words themselves are never in the repo.
- No phone number, in any format.
- No filler words in the copy.
- No line in an architecture diagram passes through a box it doesn't connect.
- Without WebGL2 you still get a dithered still image, and with reduced motion you get a still frame.
