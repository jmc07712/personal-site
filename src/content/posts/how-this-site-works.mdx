This site is designed as a desktop, with windows you can open, drag and close. Behind them, the wallpaper shows an AI agent with a core and six tool nodes on tethers. A quarter of a million particles of data move between them, and everything on the page is drawn in two colors.

I wanted the site to reflect the work I do. Most of my job involves AI agents and the data infrastructure beneath them, so the wallpaper depicts an agent with data flowing through its tools. This post explains how it is built.

## One GPU, one dither

The wallpaper combines two very different techniques in a single renderer.

The agent is raymarched. A fragment shader describes the core and its tool nodes as signed distance functions. It marches a ray through each pixel to find the surface, then lights it with soft shadows.

The data consists of 262,144 particles. Their positions and velocities live on the GPU and update through WebGL2 transform feedback. Each frame, every particle adds a small amount of ink to one cell of a half-float buffer at the site's pixel scale.

A single composite pass brings the two together. It raymarches the hub and multiplies the particle ink into it, and an 8×8 Bayer dither then reduces the result to exactly two colors.

```glsl
float bayer2(vec2 a) { a = floor(a); return fract(a.x * 0.5 + a.y * a.y * 0.75); }
float bayer4(vec2 a) { return bayer2(0.5 * a) * 0.25 + bayer2(a); }
float bayer8(vec2 a) { return bayer4(0.5 * a) * 0.25 + bayer2(a); }
```

This is the closed form of the classic matrix, computed directly in the shader, and a unit test confirms it matches the recursive 8×8 version. Because the particles and the agent share the same dither, the particles render as 1-bit pixels that belong to the same image.

The dither pattern is anchored to the page. Its threshold indices are offset by the scroll position, so the pattern stays fixed to the document as you scroll.

## What the particles represent

The particle count is tied to real data. The Insights API I led serves about 1.2 billion records a month, so each of the 262,144 particles represents about 4,578 records. On a phone the scene runs 32,768 particles, each representing about 36,621 records.

## Three moments

On a first visit, the site plays a boot sequence. Particles flow in on curl-noise currents and spell my name in the pixel font used by the menus, then collapse into the agent's core as the desktop appears. The sequence plays once per session on wide screens with motion enabled, and Restart in the menu replays it. A short inline script makes that decision before first paint, which prevents the page from flashing. If anything fails, the content reappears after eight seconds.

After the boot, the agent idles in the wallpaper. Particles travel along the tethers between the core and the tools, and each tether pulses when its tool dives into the core to represent a tool call. Moving the cursor pushes the particles aside, and they return once it passes.

The Experience window presents my career as a distributed-trace waterfall. When it is on screen, particles flow out of the agent into the three role bars. Because those bars sit inside a draggable window that other windows can cover, particles drawn in the wallpaper would show through anything on top. Instead, each bar contains a small 2D canvas that copies its region of the GPU canvas every frame, so it moves and stacks like the rest of the window.

As you scroll further down the page, the particles leave the agent and gather around the window that fills most of the screen. When you return to the top, they flow back into the core.

## The rest is a standard web app

Beneath the wallpaper, most of the site is a conventional Next.js application.

Every window body is rendered on the server, and closed windows remain in the HTML so search engines and screen readers can read all of the content. Only the window chrome, the trace, a copy button and the scene run on the client. Case files and posts have their own URLs. Opening one pushes `/work/<slug>` or `/blog/<slug>`, and the back button closes it. Loading one of those URLs directly opens the desktop to that file.

The only time-dependent input on the site is the current date, which sets the end of the trace. Next.js 16 requires an explicit decision about how to handle the clock, so the server computes the trace geometry and caches it for a day. The page stays static while the bars stay current.

On phones the site becomes what I call Pocket mode. It opens on a home screen showing the agent and an app grid. Each section appears as a framed window over a live wallpaper of 32,768 particles running at 30 frames per second. The scene sleeps after 20 seconds without input to save battery.

## Guardrails as tests

Some rules matter more than any single feature, so they are enforced as tests. One test checks the content for internal project names and colleagues' names by comparing hashes, so the repository stores only hashes of the restricted terms. Other tests keep my phone number off the site and remove filler words from the copy. A diagram test ensures that each connecting line touches only the two boxes it joins. Browsers without WebGL2 receive a dithered still image, as do visitors who prefer reduced motion.
